## Current bounded D4 socket interface

Cooling commands now use the owned executor. A successful reply means matching
ACKs **and subsequent status readback**, not a host policy or persistence claim.
No desired state, revision, configuration, or previous snapshot is updated.

| Request | Accepted fields | Current behavior |
| --- | --- | --- |
| `set_manual` | `rpm`: integer 0 or 500..4000 | Enter realtime, then set target; fresh supply limits still apply. Zero stops the fan, not the device. |
| `set_automatic` | none | Enter realtime only. No sensors, thermal loop, curve, or Smart Speed policy is implemented. |
| `set_gear` | `gear`: quiet/standard/strong/overclock; `rpm`: official choice from L17 | Exit realtime, then apply gear; reject unavailable supply/gear combinations. A fresh matching active gear/target is a no-op, avoiding a duplicate flash write. |
| `set_standby` | `standby`: off/instant/delayed | Apply standby and confirm its status bits. |

Extra fields on these four requests are rejected. Type/range validation occurs
before discovery/open; supply-dependent validation requires fresh device status.
Cooling requests to an asleep device fail with `device is asleep; wake is unsupported`.
Manual null remains unsupported with the exact L17 error. RGB, curves, host
persistence and sensors remain unsupported; existing empty sensors/gears/config
responses, status and one-snapshot subscribe semantics are unchanged.

Successful requests return `{"reply":"ok","readback_confirmed":true,"reports_sent":N}`,
where N is 0 for a matching active-gear no-op, otherwise 1 or 2. Automatic also
returns `"warning":"realtime entry only; host thermal control is unsupported"`.
Errors return `{"reply":"error","message":"..."}`. Examples: `no device yet`,
`rpm must be an integer`, `unexpected field: rpm`, and
`missing ACK for 0x21; readback required before another command`.
Readback confirms mode/target/gear/standby, **not** measured fan convergence or
successful firmware flash persistence. Request `status` for an independent snapshot;
it still does not infer manual/Smart Speed policy from realtime mode.

The executor rediscovers the first USB-first endpoint for every socket mutation.
It uses the shared guarded character-device opener with read/write, nonblocking,
no-follow, no-controlling-terminal and close-on-exec flags; it never creates or
truncates a node. Each report comes only from `command::encode`, is sent once in
one write, waits at least 5 ms before sending, and requires a checksum-valid ACK
with the same opcode and exactly one payload byte equal to 1. It drains queued
input before writes and before waiting for new status. ACK waits are 250 ms;
status and input-drain waits are bounded at 750 ms each (status cadence is 500 ms).
All failures stop immediately: no remaining reports, automatic replay, rollback,
or optimistic success. Every subsequent execution requires a new status/supply
readback. Other writers cannot be correlated by this protocol's opcode-only ACKs;
exclusive device use is a deployment assumption, not a capability proved here.
